# D1-17…D1-28 — Kế hoạch kiểm thử toàn diện (làm sau khi code xong)

> **Cho người kiểm thử:** chạy đúng thứ tự G → B → I → U → D → S → F → R. Mỗi test có ID, lệnh/thao tác, kết quả kỳ vọng. Ghi PASS/FAIL + bằng chứng vào bảng ở §10. Không được tuyên bố "xong" khi còn FAIL chưa giải thích.
>
> **Cho AI thi hành:** file này KHÔNG phải kế hoạch code. Khi nhận lại bản implement, hãy chạy đủ các mục dưới đây và báo cáo theo mẫu §10 — kể cả FAIL.

**Trạng thái tính đến lúc viết file:** D1-17, D1-19, D1-21, D1-28 đã có code + test; D1-26 đang làm dở; D1-23/24/25 chưa có code. Các mục B/I/U/D/S/F ghi rõ `(sau khi D1-xx xong)` cho phần chưa có.

**Quy tắc bằng chứng**

- Mỗi test: `PASS`/`FAIL` + lệnh đã chạy + trích output ≤ 10 dòng (hoặc ảnh chụp màn hình cho test UI).
- FAIL phải kèm: bước tái hiện, kỳ vọng, thực tế, log/lỗi nguyên văn.
- Test UI nào cũng phải thử **cả đường lỗi**, không chỉ happy path.
- Trong lúc test **không sửa code**. Ghi lỗi, sửa sau, chạy lại đúng test ID đó.
- Test có ghi file: chụp hash trước/sau để chứng minh "không đổi" hoặc "đổi đúng chỗ".

## 3. IPC & preload (I)

Chạy `npm run dev`, mở DevTools của **cửa sổ chính** (Ctrl+Shift+I), dán từng dòng vào Console.

| ID | Lệnh trong Console | Kỳ vọng |
|---|---|---|
| I1 | `Object.keys(window.pixelmind).sort().join(',')` | Có đủ namespace: `a11y, mock, deploy, auth, cloud` + các namespace cũ. Không có `env`, `secrets`, `tokens` |
| I2 | `await window.pixelmind.mock.state()` | Object `{ status: 'idle' ... }`; không throw |
| I3 | `await window.pixelmind.deploy.state()` *(D1-26)* | State rỗng, có `status`, `url`, `error`; **không** chứa token |
| I4 | `await window.pixelmind.auth.state()` *(D1-23)* | `{ status: 'signed-out' }` (hoặc signed-in với `user.email`), **không** có `access_token`/`refresh_token`/`accessToken` |
| I5 | `JSON.stringify(await window.pixelmind.auth.state())` | Không khớp `eyJ` (không có JWT) |
| I6 | `await window.pixelmind.cloud.members()` *(D1-24)* khi chưa đăng nhập | `{ success: false, error: '...' }` có câu tiếng Việt, **không** throw vỡ UI |
| I7 | `await window.pixelmind.a11y.scan({ axeSource: 'throw new Error("x")' })` | Trả `ok: false` + `reason: 'failed'` (không làm sập main, không treo Console) |
| I8 | `await window.pixelmind.mock.start('.', { port: 1, routes: [] })` (cổng đặc quyền/bận) | Trả state `status:'error'` có số cổng; main vẫn sống (gọi I2 được tiếp) |
| I9 | Đăng xuất (UI) rồi `await window.pixelmind.auth.state()` | Về `signed-out`; gọi lại I4 vẫn không lộ token |
| I10 | `npm run check:api` sau khi thêm feature | exit 0 (chạy lại lần nữa sau mỗi plan hoàn thành) |

**Vì sao có I:** unit test không chứng minh dây IPC đúng. `tsc` chỉ bắt thiếu method, không bắt thiếu `ipcMain.handle` (G4 bắt) và không bắt payload sai kiểu.

## 4. Giao diện & luồng người dùng (U)

Mỗi mục: thao tác → kỳ vọng nhìn thấy. Chụp ảnh trạng thái lỗi, không chỉ trạng thái đẹp.

### U17 — Biến thể Part (D1-17)
1. Workbench → tab **Part** → **Tạo Part mới**, dán HTML có `{{size}}`, thêm 2 biến thể ("Nhỏ" `sm`, "Lớn" `lg`) → Lưu.
   - Thẻ Part hiện ô chọn **Biến thể**; Part **cũ** (fixture) không hiện ô này.
2. Chọn "Nhỏ" → **Chèn** → mã nguồn có `sm`, không còn `{{...}}`; chọn "Lớn" → chèn → khác đúng JSON.
3. **Sao chép mã** khi đang chọn biến thể → clipboard khớp lần chèn gần nhất.
4. Nhập JSON biến thể sai (`{`) → Lưu → báo lỗi rõ ràng, không lưu part rác, không crash.
5. Biến thể chứa `<script>alert(1)</script>` → Lưu → bị chặn/không thực thi (quét code suspicious).
6. Chọn biến thể rồi đổi sang Part khác và quay lại → lựa chọn không áp nhầm Part khác.
7. Bàn phím: Tab tới ô Biến thể, chọn bằng ↑/↓, Enter không tự chèn ngoài ý muốn.

### U19 — Accessibility Checker (D1-19)
1. Dự án HTML fixture, **chưa chạy** → menu **Công cụ → Kiểm tra trợ năng** → **Quét** → thấy "Chưa tìm thấy khung xem trước…" (**không** phải "0 lỗi").
2. Chạy dự án (F5) → Quét → ≥ 2 vi phạm (ảnh thiếu alt, nút icon, input không label), nhóm theo mức độ, mỗi mục có selector + hướng dẫn; nút mở trang hướng dẫn mở đúng.
3. Sửa `alt` → tải lại canvas → Quét lại → số vi phạm giảm đúng mục đã sửa.
4. Quét 2 lần liên tiếp → danh sách **thay** chứ không cộng dồn/trùng.
5. Dự án nhiều iframe (MultiPageCanvas) → chỉ quét frame của trang đang xem.
6. Trang preview có CSP chặn script → quét → thông báo "không quét được" (reason `blocked`), không văng lỗi.
7. Đóng dialog khi đang quét → không lỗi "setState on unmounted"; quét lại được.

### U21 — Mock API (D1-21)
1. **Công cụ → Mock API**: cổng `4500`, route `GET /api/hello`, status `201`, body `{"hello":"world"}` → Lưu → Khởi động. Trạng thái chuyển `running`, hiện URL/cổng thật.
2. `curl.exe -i http://127.0.0.1:4500/api/hello` → `HTTP/1.1 201`, body đúng, có `Access-Control-Allow-Origin: *`.
3. `curl.exe -i -X OPTIONS http://127.0.0.1:4500/api/hello` → `204`.
4. `curl.exe -i http://127.0.0.1:4500/api/hello?q=1` → khớp route; `/api/unknown` → `404` JSON, kết nối đóng.
5. Frontend dự án `fetch('http://127.0.0.1:4500/api/hello')` → đúng status/body (kiểm tra tab Network).
6. **Dừng** → `curl` = connection refused; `netstat -ano | findstr :4500` rỗng.
7. Dừng rồi Khởi động lại ngay (5 lần) → lần nào cũng bind được (không kẹt cổng trên Windows).
8. Đặt cổng đang bận (cổng dev server) → Khởi động → báo đúng số cổng, không có listener mới.
9. Nhập body JSON hỏng trong dialog → Lưu → báo lỗi validate; đóng/mở lại dialog không mất cấu hình cũ.
10. Mở dự án khác → cấu hình mock của dự án trước **không** xuất hiện (lưu theo `.pixelmind/mock.json`).
11. Thoát app khi mock đang chạy → không còn tiến trình treo (Task Manager không có process con).

### U28 — Đồng bộ style từ Canvas (D1-28)
1. Dự án Tailwind v3 có `<div className="p-4">`; Settings → **Canvas & Soi** → **Đồng bộ style từ Canvas** = *Tự động*.
2. Canvas: chọn `div`, `padding = 8px`, `background-color = đỏ` → **Lưu thay đổi vào mã nguồn thật**.
   - File: `className` có `p-2` (thay `p-4`, **không** thành `p-4 p-2`), có class màu; `style` không còn `padding`.
3. Lưu lần 2 không đổi gì → `git diff` rỗng (idempotent).
4. Ctrl+R tải lại canvas → đúng padding/màu; file không có `style` trùng.
5. Đổi `writing-mode = vertical-rl` → Lưu → `style={{ writingMode: "vertical-rl" }}`, toast báo giữ inline.
6. Chế độ **Inline style** → đổi màu → Lưu → chỉ `style`, không sinh class.
7. Chế độ **Tailwind class** trên project **v4** → Lưu → kết quả/log ghi `v4` (không phải v3).
8. Project **không có** `.pixelmind/tokens.json` → Lưu → vẫn ra class hợp lý bằng token mặc định (không rơi hết về inline).
9. File `.html` thuần (không JSX) → thuộc tính residual phải là `background-color`, **không** `backgroundColor`.
10. Chọn chế độ rồi khởi động lại app → Settings giữ đúng lựa chọn.
11. Element có sẵn `style={{...}}` và `className={...}` động (template string) → Lưu → không ghi class (dùng inline), không phá cú pháp.

### U26 — Deploy & Preview URL (D1-26) *(sau khi xong)*
1. Settings → tab **Triển khai**: chọn provider, nhập token → **Lưu token an toàn** → ô input xoá, hiện "Đã lưu token (không hiển thị lại)."; **Xoá token** → về "Chưa lưu token…".
2. **Triển khai** dự án thật → log chạy theo thời gian thực; thành công → URL bấm được, **Sao chép** đúng, **Mở** mở trình duyệt.
3. Sau khi thành công, đóng app, mở lại dự án → hiện "Lần triển khai trước: …" (đã lưu `ProjectMeta.deployUrl`).
4. Lệnh sai (đổi `deployCommand` thành `exit 3`) → log + thông báo lỗi cụ thể, không treo dialog, nút chạy lại được.
5. Lệnh treo (`ping -t 127.0.0.1`) → sau timeout 5 phút tự dừng, báo "Quá thời gian triển khai…" (test nhanh: tạm đặt timeout nhỏ trong code test, không sửa code sản phẩm).
6. Không có token: chạy lệnh dùng CLI đã đăng nhập sẵn → vẫn chạy; nếu CLI đòi token → log lỗi rõ, không lộ biến môi trường.

### U23/24/25 — Đăng nhập · Đồng bộ · Quyền *(sau khi xong)*
1. Chưa có `.env` → dialog đăng nhập báo chưa cấu hình, không có nút tạo phiên, đăng nhập trả lỗi.
2. Sai mật khẩu → "Email hoặc mật khẩu không đúng."; user chưa xác nhận → câu "chưa xác nhận email"; 429 → "thử quá nhiều lần".
3. Đăng nhập đúng → hiện email, trạng thái `signed-in`; đóng/mở lại app → tự khôi phục phiên (không hỏi mật khẩu).
4. Đăng xuất → về `signed-out`; mở lại app → **không** tự đăng nhập lại.
5. D1-24: hai phiên (app + bản sao portable/VM) cùng workspace — sửa Settings ở A → **Đồng bộ ngay** → ở B **Đồng bộ ngay** → B nhận thay đổi; sửa ngược lại ở B → A nhận.
6. Xung đột: sửa cùng khoá ở cả A và B khi offline rồi đồng bộ → có cảnh báo xung đột, bản local được ghi vào `cloud-conflicts/` **trước** khi nhận remote; không mất bản nào.
7. Viewer: dialog hiện vai trò Viewer, nút đồng bộ bị vô hiệu/giải thích; nếu vẫn bấm được → phải bị chặn ở main với câu rõ ràng.
8. Owner đổi role một thành viên → thành viên đó mở lại app thấy vai trò mới.

## 10. Mẫu báo cáo

```markdown
## Kết quả kiểm thử — <ngày> — commit <sha>

### Cổng chặn
| ID | Kết quả | Bằng chứng |
|----|---------|-----------|
| G1 | PASS    | exit 0, không error TS |
| G2 | PASS    | 20/20 file test, 0 fail |

| ID | Kết quả | Bằng chứng / lỗi |
|----|---------|------------------|
| U21.6 | FAIL | Sau Dừng, `netstat -ano | findstr :4500` còn LISTENING (PID 1234). Tái hiện: start → stop. Log: ... |
...

### Tổng kết
- PASS: x/y
- FAIL: (danh sách ID + mức độ: chặn phát hành / nên sửa)
- Chưa test được: (ID + lý do: thiếu tài khoản, thiếu mạng, ...)
```

**Điều kiện để coi là "đạt":** G1–G9 PASS, không FAIL ở S5/S6/S7 (quyền phải do server quyết định), không FAIL ở F2 (mất dữ liệu), và mọi FAIL còn lại được ghi rõ + người quyết định chấp nhận.

## Không làm trong đợt test này (YAGNI)

- Không test trên macOS/Linux (chỉ Windows, theo môi trường hiện tại).
- Không test tải đồng thời nhiều máy (>2 phiên), không đo hiệu năng sync với payload lớn.
- Không test đa ngôn ngữ (chỉ tiếng Việt), không test theme tuỳ biến.
- Không tự động hoá UI (Playwright/Spectron) — test UI làm tay; nếu muốn tự động hoá thì thành việc riêng.
